# Phase 1 核心触控原型

> 本文记录原型阶段的计划与证据。当前支持范围和迭代安排见[后续开发计划](../README.md#后续开发计划)。

## 使用与构建

`0.0.2-probe` 仅对应用自己的横屏画布注入。手机上的 Shizuku 和无障碍入口均走系统授权。实际手柄测试需要实体手柄，合成序列测试使用固定输入样本并由画布记录系统收到的触控。

1. 在手机安装 Debug APK 并打开「安卓手柄控制台」。
2. 测 Shizuku 时选「授权 Shizuku」并确认系统弹窗。测无障碍后端或前台外输入服务时，通过「开启无障碍服务」启用「安卓手柄控制台 · 手柄输入」。
3. 选择后端，打开横屏测试画布。用「短序列」检查是否收到触控。用「5 分钟序列」检查持续并发，用「手柄测试」检查真实输入。
4. 实体测试时，先推左摇杆，再移动右摇杆，同时快按 RB、长按 LB。松手后画布应显示当前触点为 0。随后检查暂停、重新开始、断连及返回。
5. 查看 ADB 日志可用 `adb logcat -d -s GamepadProbe:I`。关注 `probe_reset`、`touch`、`key`、`input`、`session_end`。`delay` 是 MotionEvent 时间到画布收到事件的差值。手柄到画布的端到端时延需要另行测量。

试验用画布点位和按键供接收测试，Windows 正式迁移数据位于 `app/src/main/assets/profiles`，两者独立。无障碍捕获使用公开摇杆 source，暂停时撤销订阅。Shizuku 需要真实用户授权，测试注入由目标 UID 约束到本 App。若 App 进程死亡，远端会尝试取消活动触点，另有会话超时。系统或服务进程同时中止时，缺少取消回执属于未确认状态。

## 架构

| 组件 | 职责 |
| --- | --- |
| ControllerInput / ControllerService | 识别外接设备，统一键码与轴数据，记录前台 Activity 或无障碍回调来源，切换期间归还输入 |
| Profile / MappingEngine | 校验版本、映射和参数。使用有效区域、径向死区、中心校准、右轴反转、相对视角、按钮边缘和释放状态生成接触点 |
| PointerStream | 维护稳定的触点 ID 和当前活动集合。后端成功后提交对应事件 |
| AccessibilityTouchBackend | 同时延续连续触点并加入新触点，以系统结果回调驱动短段队列 |
| ShellTouchService | 同一 shell 进程构造持续 MotionEvent 流，通过 Shizuku UserService 调用输入管理器并检查每次路由结果 |
| ProbeRuntime / ProbeView | 只在自己的横屏测试窗口开启会话，记录事件顺序、肩键加入、右摇杆并发时的移动和最终活动触点 |

## 自动验证

`assembleDebug testDebugUnitTest lintDebug` 通过。九项 JUnit 覆盖配置资产、非法输入、死区、设备中心、有效区域、肩键与双摇杆状态、快速按键、暂停恢复、技能瞄准、连点、后端失败取消。Lint 对较低 targetSdk、反射 API 及原型界面等产生警告。

## 真机验收口径

- 目标机先通过测试画布验证。合成按键序列可证明 Android 上实际收到多点触控，实体手柄和目标游戏另行记录。
- 核心通过条件为一套后端能接收双摇杆与肩键同时活动，肩键退出后保留两根连续指针，结束时接收端指针归零。三项需从同一个连续流观察。
- 进入 Phase 2 后再验证目标窗口追踪、有效显示区域校准、编辑状态关闭映射、离线使用及两份正式配置的游戏操作。

## 实机调查补充

手机连接后，系统识别为 Xbox Wireless Controller（VID 045E，PID 0B13，采样时 ID 12）。Android 事件源含 GAMEPAD、JOYSTICK 和 KEYBOARD。左轴 X/Y、右轴 Z/RZ，归一化范围均为 -1～1。方向键走 HAT_X/HAT_Y。扳机 LTRIGGER/RTRIGGER 同时别名到 BRAKE/GAS，范围为 0～1。Linux 层扳机原始值范围为 0～1023。已读取设备能力，原型回调的实际持续输入仍待验证。

真机打开的「手柄·阿西西」手柄可视化页显示双摇杆圆盘、扳机数值和按键反馈区域，以及型号、VID/PID、最近键码和扫描码。实机画面可见系统输入、两个震动马达和体感未上报。该页未见死区或数值化双摇杆轴栏。版本 1.0.6 的已安装包清单中，唯一导出的 Activity 是 launcher。两 App 同时运行时的事件竞争仍待验证。

## Shizuku 真机等效输入结果

0.0.2-probe 在 2509FPN0BC 上验证。测试画布为横屏 2464 × 1200。短序列收到 18/18 次 RB 按下和抬起。长序列 17:57:18.049–18:02:18.064，100/100 次 RB 短按、51/51 次 LB 长按的触点都在两根摇杆活动时加入并退出。肩键退出时仍有两个活跃指针，整个序列保持同一 downTime。肩键按住时收到 2115 次改变右摇杆触点位置的 MOVE。无意外 CANCEL。结束时预期的 CANCEL 使触点归零。

按日志记录的 305 个非 MOVE 事件估算，MotionEvent 事件时间到画布接收的中位数为 1 ms，P95 为 2 ms。该数值未包含按键采样、游戏响应和渲染。Shizuku 实机注入证据来自合成控制输入，后端通过 Android 投递到了真实画布。
## 实体手柄与无障碍对照

原型读取 Xbox Wireless Controller（ID 12）。日志证明两个摇杆轴及肩键回调来自 AccessibilityService。RB 键码 103、LB 键码 102。实体手柄测试中，有 3 次 RB 短按和 4 次 LB 操作在左右摇杆同时活动时加入第三触点并退出。松开后收到 ACTION_UP，活动触点为 0。应用暂停回执为成功。

单独选择无障碍注入时，设备收到两根摇杆触点约 0.5 秒后返回系统取消，未观察到肩键加入或随后归零的回执。该后端尚未达到本机复合控制门槛。公开 API 的延续条件、未产生有效 MOVE 的连续段、系统级手势竞争均需进一步区分。Shizuku 已满足 Phase 1 真机核心并发门槛，可进入目标游戏集成。后台的目标窗口识别与输入归还、断连重连以及游戏实战留在后续阶段验收。

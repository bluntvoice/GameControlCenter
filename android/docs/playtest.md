# 安卓手柄控制台使用与验收

## 安装和控制

1. 在 Android 14 或以上设备安装 Debug APK。当前实测设备为 2509FPN0BC，Android 17 / API 37。手机拒绝 ADB 安装时，使用系统 APK 安装器确认。
2. 将实体手柄直连手机。在「控制」页检查手柄、无障碍和 Shizuku。
3. 开启「安卓手柄控制台 · 手柄输入」无障碍服务。Shizuku 已启动时，在控制台点「授权 Shizuku」并确认。非 Root 手机上可按 Shizuku 指南无线启动。 [Shizuku 使用指南](https://shizuku.rikka.app/guide/setup/#start-via-wireless-debugging)
4. 在「方案」选择超燃竞技场－三技能或激战先锋，返回「控制」点「开始控制」。打开相应玩法后，使用左摇杆、右摇杆和肩键。
5. 游戏内悬浮条提供「暂停」和「停止」。按住左侧点阵可拖动，位置会保留。返回桌面、窗口变化或手柄断开后，重新接回手柄，回到横屏游戏，点「继续」。
6. 在「方案」点「在游戏内编辑」，或在游戏暂停后点浮层「编辑」。拖动触点。选中左摇杆后可调范围。保存写入当前本地方案，取消放弃修改。

## 手柄与触屏并用

在 Android 17 设备、Shizuku 已授权的情况下，可开启「设置 → 手柄与触屏并用」，再回到「控制」点击「开始控制」。此 Beta 功能默认关闭。开启后，在主屏横屏的《蛋仔派对》中可以用左摇杆移动，同时用手指拖动视角或点击技能。

暂停、停止、离开游戏、锁屏、手柄或触控服务断开时，控制台退出并用并恢复系统触摸。开启触摸探索时，开始并用会显示不兼容提示。旧版 Android 和纯无障碍触控后端沿用原控制方式。

## 方案管理与诊断

- 「方案 → 复制方案」填写名称后创建并选中手机副本。激战先锋默认副本名为「激战先锋（手机）」。副本有独立 ID，修订从 1 开始，保留来源和未映射的鼠标节点。以后交换配置时以各自 ID 识别。
- 「设置 → 游戏内悬浮显示」可开关键位提示，分别设置键位提示和悬浮条的不透明度。键位用不带底框的彩色文字显示在对应触点，手柄按下时以相同颜色短暂闪亮。触摸可穿过标签。悬浮条盖住一个正在使用的映射触点时会暂停并提示移开。
- 方案采用版本化 UTF-8 JSON，通过 Android 文件选择器导入。重名依稳定 ID 区分，导入与本地同 ID 的不同内容时生成副本。
- 方案参数和触点保存到 App 本地。内置方案可恢复原始配置。手柄中心校准与右轴反转偏好保存在单独的设备设置中。
- 「诊断」页显示摇杆、扳机、按钮、设备 ID、输入来源、死区和最后一次输入。放开摇杆后可用最近现场读数校准中心。
- 「设置」显示运行状态记录、默认后端、死区、左右摇杆灵敏度、轴反转和点击时长。右摇杆把方向和推杆幅度转换为视角拖动速度。调整后保存。左摇杆灵敏度 100% 保持原响应。
- A、B、X、Y 使用电脑版的绿色、红色、蓝色、黄色。方向箭头、肩键和其他按键可用「设置 → 其他按键配色」输入任意 RGB 色值。左右摇杆标签为「左」「右」。
- 自动模式优先 Shizuku。无障碍注入仍提供手动兼容性测试。Shizuku 不可用时，首页显示对应状态。

## 实现范围

- Material 3 / Compose、系统动态取色、深浅主题、控制 / 方案 / 诊断 / 设置。
- 两套配置来自 Windows 正式配置。激战先锋的鼠标右键节点无实体手柄对应项，原始数据保留。
- 游戏会话只在核实目标包前台、横屏和区域后接管，游戏触控使用 Shizuku 已授权的 shell 输入调用。派发期间分别检查无障碍游戏窗口和 shell 前台任务。注入失败后暂停并显示错误。控制中的游戏窗口区域变化会停止当前触点，再由用户继续。
- 游戏内编辑显示当前方案的触点和左摇杆范围，暂停映射输入。储存通过校验和原子写入，当前 Android 方案与 Windows 源配置相互独立。
- App 清单无 INTERNET 权限。配置解析、管理、输入和注入均在本机。游戏服务连接由《蛋仔派对》自行决定，独立游玩仍需按实测报告区分。

## 真机验收口径

1. 日志的「可以控制」表示选定会话、窗口、设备和服务已准备。首次非空触点被后端接受后显示「控制中」。
2. 用户在两个玩法分别验证移动、转向、技能、组合输入与松开。系统接受事件的证据与游戏内响应分别记录。
3. 确认暂停、切换应用、锁屏、手柄断连、Shizuku 停止和无障碍退出时的可观察状态及触点清理。系统进程强停情况下，清理回执可能不可获得。
4. 检查拖动后保存、取消、恢复原始、进程重启读回、离线时的本地方案和映射路径。完成后再考虑正式 v0.1.0。

## HyperOS 触控兼容

0.0.4 在横屏识别了游戏窗口和实体手柄，但系统拒绝 UID 定向触控。InputDispatcher 记录了 PointerEventDispatcherOverlay0、MultiTaskSwitch 和 swipe-up 手势窗口也在派发路径中。0.0.5 的游戏会话改用 shell 允许的双参数输入接口。触控 App 端复核前台游戏窗口和有效区，UserService 端复核当前主屏前台任务。单独测试画布仍使用自身 UID 的定向触控。切换焦点时会停止发送触点，并尝试取消已有手势。两个前台检查是独立调用，仍存在系统窗口在检查和派发之间变化的时间窗口。 [AOSP InputDispatcher](https://android.googlesource.com/platform/frameworks/native/+/a51585cb19988cd9bc1af8d4ab0a3e66b664cef7/services/inputflinger/dispatcher/InputDispatcher.cpp) · [AOSP 输入入口](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/hardware/input/InputManagerGlobal.java)
